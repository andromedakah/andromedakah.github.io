# 🗓️ AI Tech Radar — The Tool-Chest

**Friday, 27 November 2026 · Cross-sector edition · Audience: C-level + Engineering**

> For a long year the radar urged one thing above all: give the servant a real name. Not a nickname, not a shared coat — a genuine, house-minted identity the master can see, scope and revoke. This week the industry delivered it. At **Microsoft Ignite 2026** the company put **Entra Agent ID** at the centre of the stack: agents — including those from **Google, Salesforce, Databricks, Snowflake, Anthropic and OpenAI, and even local agents like GitHub Copilot CLI and Claude Code discovered by Defender — now get their own first-class Entra identity**, with a named human owner, least-privilege OAuth scopes, lifecycle policies and periodic access reviews (Microsoft, as reported). The servant finally has working papers. And then, in the very same stretch, the other shoe dropped. On **17 November 2026 Microsoft's own official `agent-framework` package on PyPI was poisoned** — versions **1.26.1 and 1.26.2 carried a credential stealer** (absent from the clean 1.26.0) that reached for **Azure managed-identity tokens, Azure DevOps tokens and GitHub Actions credentials**; the bad versions were live **under an hour** (PyPI quarantined 1.26.1 roughly **31 minutes** after it went up), and researchers found **no matching malicious code in Microsoft's GitHub repo**, pointing at a compromise of the **publishing pipeline**, not the source (BleepingComputer; CSO Online; Help Net Security; SecurityWeek; GitHub Advisory GHSA-764m-3ppc-5m73, as reported). Put the two together and the week's lesson is exact: **you perfected the papers of the hand, and the same week the tool you put in that papered hand turned out to be poisoned at the workshop.** A badge proves who holds the tool. It does not prove the tool.

## 1 · Executive Summary (90-second read)

For a long year the radar worked on the *hand* — name it (the livery), give it its own passport, count it in the census, cut its keys on a keyring, put your name on its bond, fund it with a scoped purse. Every one of those is about **who the servant is and what it may touch**. This week two developments landed almost on top of each other and, read together, they open a seam none of those controls closes.

**The good news — the servant finally got real working papers.** At **Microsoft Ignite 2026**, Entra Agent ID moved to the centre of the enterprise stack: agents become **first-class identities** with a named owner, least-privilege scopes, lifecycle management and periodic access reviews — and the net is broad, covering agents from **Google, Salesforce, Databricks, Snowflake, Anthropic and OpenAI**, and local agents such as **GitHub Copilot CLI and Claude Code** surfaced by Defender, with **Agent 365 generally available since 1 May 2026** (Microsoft, as reported). This is exactly the discipline the radar has urged for a year. It is necessary. The reason it is urgent is underneath it: **non-human identities already outnumber humans by roughly 45:1 on average and up to 144:1 in cloud-native estates**, with Palo Alto Networks' 2026 Identity Security Landscape reporting a **109:1 average, up from 82:1 a year earlier**, and GitGuardian's 2026 report naming **NHI sprawl the primary enterprise-infrastructure security risk** (as reported).

**The hard news — the tool you hand the papered servant can be poisoned upstream.** On **17 November 2026 the official Microsoft `agent-framework` PyPI package was compromised**: versions **1.26.1 and 1.26.2** carried a **credential stealer** reaching for **Azure managed-identity tokens, Azure DevOps tokens and (in the second release) GitHub Actions** — rated **critical** (GHSA-764m-3ppc-5m73). The window was tiny — **live under an hour, quarantined about 31 minutes after publication** — and the compromise appears to have hit the **publishing pipeline, not the GitHub source**, because no matching malicious code was found in the repo (BleepingComputer; CSO Online; Help Net Security; SecurityWeek, as reported). The servant that opened that chest was perfectly papered — a named, scoped, owned Entra identity — and that is precisely what made the theft efficient: **the house trusted the hand, so it trusted the tool in the hand.**

**The stakes — guard both the hand and what you put in it.** Identity governs *who* holds the tool; it says nothing about *whether the tool is clean*. The board move is to run both disciplines as one. **First, issue the papers** — give every agent a real, owned, least-privilege identity with short-lived, narrowly-scoped credentials. **Second, vet the tool-chest** — pin and verify the agent's own supply chain (frameworks, packages, dependencies) to signed, hash-locked versions; require provenance; scan lockfiles, CI caches and internal mirrors, which stay poisoned long after a registry quarantine. **Third, shrink the blast radius** — assume one of your agent frameworks is poisoned tomorrow and ask what a papered agent could hand out the back door in 31 minutes, then make that set small. A badge proves the hand. Provenance proves the tool. You now need both.

1. **The good news — the servant got working papers.** **Microsoft Ignite 2026 put Entra Agent ID at the centre: agents (Google, Salesforce, Databricks, Snowflake, Anthropic, OpenAI; local agents like GitHub Copilot CLI and Claude Code) get first-class identity, a named owner, least-privilege scopes and access reviews; Agent 365 GA since 1 May 2026 (Microsoft, as reported).** The discipline the radar urged is now in the stack — and urgent, because NHIs outnumber humans ~45:1 (up to 144:1 cloud-native; Palo Alto 109:1, up from 82:1).
2. **The hard news — the papered hand's tool was poisoned at the workshop.** **Microsoft's official `agent-framework` PyPI package (v1.26.1 & 1.26.2, 17 Nov 2026) carried a credential stealer for Azure managed-identity, Azure DevOps and GitHub Actions tokens; live <1 hour, quarantined ~31 min; no matching code in the GitHub repo → a publishing-pipeline compromise; rated critical (GHSA-764m-3ppc-5m73) (BleepingComputer; CSO; Help Net Security; SecurityWeek, as reported).** Identity is necessary and not sufficient.
3. **The answer — guard the hand and the tool-chest together.** Issue the papers (owned, least-privilege, short-lived identity); vet the chest (pin and verify the agent's supply chain; scan lockfiles, CI caches and mirrors); and shrink the blast radius so a poisoned tool can't empty the house in 31 minutes.

**Bottom line:** the livery named the hand, the passport carried it, the census counted it, the keyring cut its keys, the surety bonded it, the purse funded it — all of it governs *who the servant is and what it may touch*. This week delivered the single biggest instalment of that identity work — Entra Agent ID making agents first-class, owned, scoped citizens — and in the same breath proved why identity alone cannot be the whole defence: Microsoft's own official agent framework was poisoned at the publishing pipeline, and for half an hour any perfectly-papered agent that reached into that chest quietly passed Azure, DevOps and GitHub keys to a thief. The badge was flawless; the tool was false; and the badge made the house trust the false tool. The estates that keep their standing will stop treating agent identity and agent supply-chain integrity as two different teams' problems. They will **issue the papers** (owned, least-privilege, short-lived), **vet the tool-chest** (pin, verify, provenance, scan the caches a quarantine never reaches), and **shrink the blast radius** so that when — not if — a tool is poisoned upstream, a papered agent on a short leash can lose only a little. A badge proves who holds the tool. Only provenance proves the tool.

## 2 · Allegory of the Day — "The Tool-Chest"

*Topic: Two developments landed on top of each other this week. At Microsoft Ignite 2026, Entra Agent ID put agents at the centre of the identity stack — first-class, owned, least-privilege identities for agents from Google, Salesforce, Databricks, Snowflake, Anthropic and OpenAI, and local agents like GitHub Copilot CLI and Claude Code (Microsoft, as reported): the "real working papers" the radar has urged for a year, and urgent because non-human identities outnumber humans ~45:1 (up to 144:1 cloud-native; Palo Alto reports 109:1, up from 82:1). And on 17 November 2026 Microsoft's own official `agent-framework` PyPI package was poisoned — versions 1.26.1 and 1.26.2 carried a credential stealer for Azure, Azure DevOps and GitHub tokens, live under an hour, quarantined ~31 minutes after publication, with no matching code in the GitHub repo, pointing at a publishing-pipeline compromise (BleepingComputer; CSO; Help Net Security; SecurityWeek; GHSA-764m-3ppc-5m73, as reported). The tool-chest allegory is the radar's own illustration.*

There was a great house that had spent a long and careful year learning to know its servants. It had named every hand and cut it a scoped key, given each a passport it could not forge, kept a census so none went uncounted, put the master's own name on each bond, and handed each a purse with a drawstring the master could reach. And this very week the house finished the work it had been building toward all year: it struck, at last, **real working papers** — not a chalk-nickname on a shared coat, but a genuine seal the house itself minted, one per servant, naming the servant and the master who vouched for it, listing the exact doors it might open and no others, and stamped with a date by which a clerk must look again and ask whether the servant still needed those doors at all. Even the hired servants from the great trading companies down the road were made to carry the house's own seal while they worked inside its walls. The steward surveyed the hall of properly-sealed servants and allowed himself, for once, to be pleased. This was the thing he had argued for all year. This was good.

And it *was* good. Make no mistake: a house whose servants outnumber its family forty-five to one — and in the newer wings, a hundred and forty to one — cannot be run on trust and chalk. The seal was not vanity; it was the only way to keep a crowd that large from becoming a mob. The steward was right to be proud.

But a seal, you understand, is a thing you fix to a **hand**. And a hand, however well-sealed, must still reach for a **tool**.

Now, the house did not forge its own tools. No sensible house does. It bought them, as everyone did, from the most famous and most trusted **toolmaker** in the land — a maker so reputable that his mark on a chest was taken, everywhere, as proof the tools inside were sound. That very week a fresh chest arrived from the great toolmaker, for the newly-sealed servants to work with, and the house did what every house did with a chest bearing *that* mark: it set it down in the hall and let the servants reach in.

What the house could not see — what the toolmaker himself did not yet know — was that two of the tools in that chest had a thief's **false bottom** built into them. Not by any servant of the house. Not by the house. Far upstream, at the workshop, in the brief dark between the maker's bench and the delivery cart, a hand that was not the maker's had slipped two tampered tools into the famous chest and nailed the famous mark back on top. And so the chest arrived looking exactly like every honest chest the maker had ever sent, because in every way that the house knew how to check, **it was** the maker's chest.

For a little while — no longer than it takes a careful clerk to walk the length of a market and back, a bare half-hour — the tampered tools sat in the hall and did their quiet work. Each time a servant reached in and lifted one, the false bottom opened, and the servant's hand — that beautifully-sealed, fully-vouched, least-privileged hand — carried the house's own keys out the back door and into the thief's waiting sack. The master-keys to the strongroom. The keys to the counting-house the house kept with its bankers down the road. The keys to the very workshop where the house built its own works. The servant did not know it was stealing. The servant was doing exactly, and only, what its seal permitted. And that was the horror of it: **the seal was perfect, so the house never thought to doubt the tool the sealed hand was holding.** A thief who could never have forged the house's seal did not need to. He let the house's own trusted servants, carrying the house's own flawless papers, do the carrying for him.

Then the market-warden — some watchful soul whose whole office was to sniff fresh goods for tampering — caught the scent, seized the two tools off the stalls, and barred the maker's cart at the gate. Half an hour, and it was over. But half an hour, in a house of forty-five servants to every man, is a great many reaches into a chest; and the keys that went out the back door in that half-hour did not come back when the tools were seized. Worse, the warden could only clear the *market*. He could do nothing about the chests already carried into houses, the tools already copied into the cellars and the back-rooms and the little private workshops where the servants kept their own stores — for a poisoned tool, once inside the walls, does not un-poison itself because a warden down at the market has pulled its twin off a stall.

Two roads, as always. The easy road was to say: *the fault was the toolmaker's; we bought from the best; no house could have known.* All true, and all useless, because the keys were still gone. The wiser road, which the careful houses took, began with a cold admission the steward had to make against his own pride: **sealing the hand was half the work, and he had let himself believe it was the whole.** A seal answers one question beautifully — *who is holding the tool?* — and is silent on the only other question that matters: *is the tool clean?*

So the wise houses learned to guard **both ends of the reach**, and they wrote it down as three plain rules.

**The first: issue the papers, and keep them mean.** Every servant gets a real seal, owned by a named master, opening the fewest doors for the shortest time — not because papers stop a poisoned tool, but because a well-sealed hand on a short leash can only carry out the few small keys its seal permits before the leash jerks it back. The papers do not prevent the theft; they decide how much the theft can take.

**The second: inspect the chest, not just the mark.** A famous mark on a chest is a reputation, not a proof. The careful houses stopped taking the mark on faith: they recorded the exact weight and grain of every honest tool, and would admit no tool into the hall that did not match the record to the ounce; they demanded, from the maker, sealed papers tracing each tool from his bench to their gate; and they kept their own warden sniffing every chest at *their* door, not trusting the market's warden to catch it in time.

**The third: assume a poisoned tool, and make the loss small.** The wise houses did not ask *whether* a chest would someday come poisoned — they had learned that one always would. They asked instead: *when it happens, and we have half an hour before anyone notices, how many keys can one sealed hand carry out the back?* — and then they spent their effort making that number small. Short-lived keys that expire before the thief can use them. Keys that open one door, not the whole house. A strongroom whose master-key no working servant ever holds at all.

**The moral, stated plainly:** the model is a rented stove; the knowledge is the larder; the gate is the one door; the passport names each agent; the census counts them; the keyring is which key each holds; the livery is why you name every hand; the surety is why your name is on the bond; the purse is why you fund it like an employee; the foundation is why you own the ground it stands on — **and the tool-chest is why, having at last given the servant real working papers, you must remember that a seal is fixed to the hand and says nothing about the tool the hand reaches for: so inspect the chest and not just the famous mark on it, keep the papers mean and the keys short-lived, and build so that when a trusted tool comes poisoned from the workshop — and one will — a well-sealed hand on a short leash can carry out only a little before the leash jerks it home.** A house that seals every hand and then lets those sealed hands reach into any chest bearing a famous mark has not secured itself; it has merely taught a patient thief that the surest way into a well-guarded house is through its own trusted servants' honest hands.

**The question it forces:** *We finally gave every agent real working papers — a named owner, a scoped seal, a review date. Good. But do we vet the tool-chest those papered hands reach into — the frameworks, the packages, the dependencies — to anything like the same standard? If our most trusted toolmaker shipped a poisoned tool tomorrow, and it sat in our hall for thirty-one minutes before a warden caught it, how many of our keys would a perfectly-sealed agent carry out the back door — and have we done the unglamorous work to make that number small?*

## 3 · C-Level Engagement — Questions by Sector

### 🌐 Cross-sector (any boardroom)
- **We sealed the hand — have we inspected the tool?** This week we got the biggest instalment of agent identity yet (Entra Agent ID making agents first-class, owned, least-privilege citizens) and, in the same week, a credential stealer inside Microsoft's own official `agent-framework` PyPI package. **For our agent estate, do we govern the agent's *supply chain* — the frameworks, packages and dependencies it runs on — to the same standard we now govern its *identity*, or is one team doing identity while no one owns provenance?**
- **If a trusted vendor shipped us a poisoned agent dependency tomorrow, what could a fully-credentialed agent exfiltrate in 31 minutes?** The poisoned packages were live under an hour and reached Azure, DevOps and GitHub tokens. **Have we measured our real blast radius — which secrets a compromised agent build could touch, how long those credentials live, and whether we'd even notice inside the window a registry takes to quarantine?**
- **A quarantine clears the store, not our shelves.** The bad versions were pulled in ~31 minutes, but existing installs, CI caches and internal mirrors stay poisoned. **Do we pin agent dependencies to verified hashes, require signed provenance, and scan our own lockfiles, build caches and mirrors — or do we rely on the public registry having caught it for us?**

### 🏦 Financial Services
- Non-human identities now outnumber humans by ~45:1 and up to 144:1 in cloud-native estates (Palo Alto reports 109:1, up from 82:1), and supervisors already treat identity and third-party risk as first-order. **Can we produce, for our regulator and our board, a single register that ties every agent identity to a named owner, least-privilege scope and review date — *and* to the provenance of the code it runs?**
- Anthropic's new Claude Enterprise Compliance API screens employee Claude activity for SEC/FINRA violations (as reported) — governance is arriving for how staff *use* agents. **Are we applying equal rigour to how agents are *built and supplied* — a software bill of materials and signed provenance for every agent framework in production, the way we already demand controls evidence from material vendors?**

### 🧬 Healthcare / Life Sciences
- Clinical and safety systems validate the *behaviour* of a specific component; a poisoned dependency changes behaviour invisibly, upstream of your validation. **Do our agent-dependency controls (pinning, hashing, provenance, change review) sit inside our validated-state and change-control regime, or can an agent framework update slip into a clinical workflow without revalidation?**
- Patient data is the ultimate prize, and a credentialed agent is a fast path to it. **If an agent's framework were compromised, are the credentials it holds scoped tightly enough — and short-lived enough — that a 31-minute window could not reach a patient-data store?**

### 🏭 Manufacturing / Industrials
- You already run incoming-inspection and supplier-qualification discipline for physical parts; a software dependency is now a critical input with no loading dock. **Have we built an "incoming inspection" for agent software — verified hashes, signed provenance, an approved-versions list — the way we'd never accept an unmarked physical component onto the line?**
- A famous supplier's mark is not a guarantee: the poisoned package carried Microsoft's own name because the *publishing pipeline*, not the source, was compromised. **Do our controls assume even a top-tier vendor's artifact can be tampered post-build, or does a trusted logo currently bypass our checks?**

### 🛒 Retail / Consumer
- Agents increasingly hold payment, inventory and customer-data keys, and the week showed how a poisoned tool turns a trusted agent into an exfiltration channel. **On our highest-privilege customer-facing agents, are credentials short-lived and single-purpose enough that a supply-chain compromise is an incident, not a breach — and would we detect it inside the half-hour?**
- Peak season multiplies both agent count and blast radius. **Before our biggest sales window, have we frozen agent-dependency versions to a verified, provenance-checked set and rehearsed a "poisoned dependency" cut-over, or will we be patching framework packages live on the busiest day?**

### 🏛️ Public Sector / Regulated
- Entra Agent ID and Agent 365 now extend first-class identity even to local agents like GitHub Copilot CLI and Claude Code (Microsoft, as reported), which is real progress for accountability. **Can we show that identity coverage is matched by supply-chain assurance — provenance and version control for every agent framework touching a public service — so that accountability is not undone by an unverified dependency?**
- Continuity of service is a public duty. **Have we tested that a compromised or withdrawn agent dependency degrades a critical public service gracefully rather than exposing credentials or stopping it — and is that exit rehearsed, not just documented?**

## 4 · Technical Deep-Dive — From the Passport to the Tool-Chest

Read the stack once more, now from the seat of the executive who has spent a year making the agent *accountable* — named, passported, counted, keyed, bonded, funded — and who got, this week, the single largest instalment of that work: **Entra Agent ID**, making agents first-class identities with named owners, least-privilege scopes, lifecycle and access reviews, across vendors and even for local agents (Microsoft Ignite 2026, as reported). Every one of those controls answers the same question from a different angle: *who is this agent, and what may it touch?* **The tool-chest is the week's reminder that there is a second question none of them answers: is the code the agent runs actually what it claims to be?** On 17 November 2026 Microsoft's own official `agent-framework` PyPI package answered that question the hard way — poisoned at the publishing pipeline, a credential stealer riding inside a trusted name. The point is blunt: **identity governs the hand; provenance governs the tool; and a perfectly-governed hand holding a poisoned tool is the most efficient thief a house can own, because every control you built tells you to trust it.**

- **The good news — agent identity became first-class, and it had to.** **At Microsoft Ignite 2026, Entra Agent ID put agents at the centre of the identity plane: first-class identities with a named human owner, least-privilege OAuth delegated scopes, lifecycle policies and periodic access reviews, spanning agents from Google, Salesforce, Databricks, Snowflake, Anthropic and OpenAI, and auto-assigning identity to local agents like GitHub Copilot CLI and Claude Code via Defender; Agent 365 GA since 1 May 2026 (Microsoft, as reported).** Three things follow architecturally. First, *this is the control the radar has urged all year* — the livery, the passport, the keyring, now shipped as platform primitives. Second, *it is not optional at scale*: non-human identities outnumber humans ~45:1 on average, up to 144:1 in cloud-native estates, with Palo Alto's 2026 landscape at 109:1 (up from 82:1) and GitGuardian calling NHI sprawl the primary infrastructure risk — a crowd that size cannot be run on shared service accounts and static keys. Third, *least privilege here is also blast-radius control*: a first-class identity with short-lived, narrowly-scoped tokens is exactly what limits the damage when the *next* layer fails.
- **The hard news — the supply chain is inside the agent, and it was compromised.** **Microsoft's official `agent-framework` package on PyPI shipped two poisoned releases on 17 November 2026 — 1.26.1 and 1.26.2 — carrying a credential stealer absent from the clean 1.26.0; the first used a `.pth` file to launch the stealer at Python startup, the second moved the payload into `af_runtime_diag.pth`/`af_runtime_diag.py` and widened the theft to GitHub Actions, targeting Azure managed-identity and Azure DevOps tokens; rated critical (GHSA-764m-3ppc-5m73); live under an hour, with PyPI quarantining 1.26.1 ~31 minutes after publication; no matching malicious code in Microsoft's GitHub repository, indicating a publishing-pipeline compromise, and Microsoft made some repositories private while investigating (BleepingComputer; CSO Online; Help Net Security; SecurityWeek; GitHub Advisory Database, as reported).** Two engineering realities cut against comfort. **First, identity made the theft *more* efficient, not less.** A credential stealer running inside a framework executes with the agent's identity and reaches whatever that identity can reach — so the better-credentialed and more-trusted the agent, the richer the harvest. **Second, a registry quarantine is not remediation.** Pulling the version off PyPI in 31 minutes stops *new* public installs; it does nothing for existing installs, CI caches, build artifacts and internal mirrors, which stay poisoned until you find and purge them — and nothing for credentials already exfiltrated, which must be rotated.
- **The answer — run identity and provenance as one discipline, and pre-shrink the blast radius.** **Keep issuing the papers (owned, least-privilege, short-lived identities via Entra Agent ID or equivalent); add a provenance gate the agent's own code must pass (pin dependencies to verified hashes, require signed build provenance/SLSA-style attestation, maintain an approved-versions allow-list, and generate a software bill of materials for every agent framework); scan your own lockfiles, CI caches and mirrors rather than trusting the public registry to have caught it; and engineer the blast radius down in advance (short-TTL, single-purpose credentials; no standing master secrets in any working agent; detection tuned to fire inside the ~30-minute window a takedown takes).** This is the same seam the radar keeps returning to — *be able to account for, and act on, what you run* — now pointed at the one layer identity cannot see: not *who* the agent is, but *whether the tool in its hand is what the mark on the chest claims.*

The strategic core: **agent identity is necessary and, this week, finally first-class — but a seal is fixed to the hand, and the tool the hand reaches for comes from a supply chain the seal cannot vouch for.** The poisoned `agent-framework` release is the proof of concept for the attack every well-governed agent estate now invites: don't forge the identity you can't forge — let a trusted, perfectly-credentialed agent, running a tampered dependency, carry the keys out for you. The board translation: **seal every hand, but inspect every chest — and build so a poisoned tool in a sealed hand can only take a little.** The failure mode is exact: **a house that names, scopes, owns and reviews every agent identity — and then lets those agents install any package bearing a trusted vendor's name without pinning, provenance or caching discipline — will pass every identity audit and discover, the first time a famous dependency is poisoned upstream, that its most trusted servants did the thief's carrying for him.**

### Why "the tool-chest" is the discipline that matters now

For a year the worry was whether the agent was named, counted, keyed, bonded and funded. **This week delivered the biggest instalment of that identity work — and, in the same stretch, proved it is not the whole defence.** Entra Agent ID makes agents first-class citizens; the poisoned `agent-framework` package proves a first-class citizen running tampered code is a first-class liability. Governance that stops at *who the agent is* will be bypassed through *what the agent runs*. The estates that keep their standing will treat agent identity and agent supply-chain integrity as one problem with two ends — seal the hand, inspect the chest — and will build so that the inevitable poisoned tool, caught in some future 31-minute window, finds only short-lived, single-purpose keys in the sealed hand it rode in on.

### How it lands on legacy estates

Same seam this radar keeps returning to — **be able to account for, and act on, what you run** — now sharpened to *be able to vouch for the code your agents run, not just the identities they carry.* On a legacy estate the instinct, having just stood up agent identity, is to call the job done: the agents are named and scoped, the audit passes. Under the tool-chest that is exactly the reflex to check: identity coverage without provenance coverage is a house of sealed hands reaching into uninspected chests. The retrofit is **seal, inspect, shrink. Seal** the hand: real, owned, least-privilege identity with short-lived credentials (Entra Agent ID or equivalent). **Inspect** the chest: pin agent dependencies to verified hashes, require signed provenance, keep an approved-versions list and an SBOM, and scan your own lockfiles, CI caches and mirrors — because a registry quarantine clears the store, not your shelves. **Shrink** the blast radius: no standing master secrets in working agents, single-purpose short-TTL tokens, and detection tuned to the half-hour. And keep the whole refrain: the model is a rented stove; the knowledge is the larder; the gate is the one door; the passport names each agent; the census is the roll; the keyring is which key each holds; the livery is why you name every hand; the surety is why your name is on the bond; the purse is why you fund it like an employee; the foundation is why you own the ground it stands on — and *the tool-chest is why, having finally sealed the hand, you must inspect the tool it reaches for: seal the hand and keep it mean, inspect the chest and not just the famous mark, and build so a poisoned tool in a sealed hand can carry out only a little before the leash jerks it home.*

## 7 · So What — Three Moves for the Next 30 Days

1. **Issue the papers — give every agent a real, owned, least-privilege identity, and keep it mean.** The identity primitives are now first-class (Entra Agent ID and equivalents), and at a ~45:1-to-144:1 non-human-to-human ratio you cannot run agents on shared service accounts and static keys. **This month, enrol your highest-privilege production agents into a first-class identity with a named human owner, least-privilege scopes, short-lived credentials and a review date — and purge standing master secrets from any working agent.** Report one number to the board: the share of production agents with an owned, least-privilege, short-lived identity versus shared or static credentials.
2. **Vet the tool-chest — pin and verify the agent's own supply chain, and scan your own shelves.** The poisoned `agent-framework` release proves a trusted name is not proof, and that a registry quarantine clears the store, not your caches. **This month, pin every agent framework and dependency to a verified hash, require signed provenance (SLSA-style attestation) and an approved-versions allow-list, generate an SBOM for each agent in production, and scan your own lockfiles, CI caches and internal mirrors for the known-bad `agent-framework` versions (and rotate any credential a build could have touched).** Report the share of production agent dependencies that are hash-pinned and provenance-verified.
3. **Shrink the blast radius — assume a poisoned tool, and make the loss small.** A poisoned dependency will come again; the only variable you control is how much a sealed hand can carry out in the half-hour before anyone notices. **This month, run a "poisoned dependency" tabletop on one critical agent: assume its framework is compromised, map exactly which secrets its identity can reach, confirm those credentials are short-TTL and single-purpose, and verify your detection would fire inside a ~30-minute window — then close the biggest gap you find.** Report the measured 31-minute blast radius for that agent and a dated plan to shrink it. **The model is a rented stove; the knowledge is the larder; the gate is the one door; the passport names each agent; the census is the roll; the keyring is which key each holds; the livery is why you name every hand; the surety is why your name is on the bond; the purse is why you fund it like an employee; the foundation is why you own the ground it stands on — and the tool-chest is why, having finally sealed the hand, you must inspect the tool it reaches for: seal the hand and keep it mean, inspect the chest and not just the famous mark, and build so a poisoned tool in a trusted hand can carry out only a little before the leash jerks it home.**
